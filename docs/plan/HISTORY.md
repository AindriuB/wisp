## 2026-10-30 — Append-only request history log
`crates/storage/src/history.rs` adds `HistoryEntry`, `Outcome` and `HistoryLog`, writing JSON lines to `<collection>/.wisp/history.jsonl` and creating `.wisp/.gitignore`. The log rotates past 4 MiB to `history.1.jsonl`; `read_all` skips malformed and invalid-UTF-8 lines, and `append` recovers from a torn last line. `preview_from` is bounded to 1 KiB on a char boundary. The URL template is stored unresolved, and no secrets, headers or error messages are stored. Code review was clean after one round; it landed as one squashed commit (4198ee4).
**Cost:** The review round fixed robustness gaps (torn last line, invalid UTF-8) rather than design. `preview_from` decodes exactly 1024 bytes, so a 4-byte char straddling the limit becomes U+FFFD; left as an optional P3. Rotation is not safe against concurrent writers (single writer in v1). Never store `ResolveWarning`s in history, because `PatternMismatch.value` can hold a resolved secret. Task 15's file was retired here.

## 2026-10-30 — M1 core types frozen, dependencies added, modules scaffolded
`crates/core` now has the frozen authoring model (`request.rs`), the final `PreparedRequest` and the `resolve` input and error types; `crates/storage` has its error type. All M1 dependencies are in the manifests and `Cargo.lock` (804 packages before and after; only dependency edges added), and empty module files exist in both crates, so tasks 11-20 can run in parallel without touching a manifest or `lib.rs`. The engine and app were adapted to the new `PreparedRequest` only. Code review was clean; it landed as one squashed commit (ec38e79).
**Cost:** Secret-bearing types derive Debug in plain text (`Request`, the defaults types via `Auth`, `ClientSettings.proxy`); only `Environment` redacts, so never log the others with `?`. The engine ignores `PreparedRequest.client` and `.warnings` until task 16, so `verify_tls=false` is not yet honoured. Task 10's file was retired here. Review P3s are in PLAN.md.

## 2026-10-29 — Measure diagnostics and first CI measurements
`measure.sh` and `measure.ps1` now capture the app's stderr (a `stderr_tail` field in the JSON), stop early on a `WISP_EVENT failed` line or process exit and report the real cause, and no longer have the 07 P3 faults. `measure.yml` discovers the Linux Vulkan ICD, installs GL userspace and runs a diagnostics step. The app exits non-zero when its window fails to open and prints `WISP_TRACE` checkpoints under `WISP_AUTOSEND_URL`; on macOS a hang produces a `sample` log. The first CI runs gave Windows and Linux release builds (run https://github.com/AindriuB/wisp/actions/runs/40964841352) and the first CI measurements, recorded in `docs/architecture.md`. It landed as one squashed commit (ff3b5f8).
**Cost:** Two root causes took several CI runs to find. (1) Linux: Ubuntu 26 names the lavapipe ICD `lvp_icd.json`, so the hardcoded `lvp_icd.x86_64.json` path pointed nowhere; discover the file, never hardcode it. (2) Intel macOS CI: the main thread blocked in AppKit window-tab setup on a synchronous XPC call to the icon service (`ISIconManager`) on the headless runner; not a Wisp bug, so x86_64-apple-darwin RSS stays unmeasured on CI. Do not retry that runner expecting different results. Task 09's file was retired here. Review P3s carried forward in PLAN.md.

## 2026-10-29 — M0 budgets recorded and GPUI kept
The Budgets section of `docs/architecture.md` now holds the M0 measurements per target and the budgets the user set from them on macOS arm64 with a hardware renderer: binary at most 20 MB (20,971,520 B), idle RSS at most 120 MB, RSS after one request at most 128 MB, about 20% over the measured 16,660,480 B, 100,032 KiB and 103,296 KiB. The user decided to keep GPUI because it builds and renders on macOS within budget. Windows, Linux and macOS x64 RSS read "not measured" and have no budget until a `measure.yml` run and per-platform budgets from the user.
**Cost:** GPUI costs the user accepted: version-pinning churn (git rev, then crates.io `gpui-pre`), a separate `gpui-pre-platform` backend crate, the Metal Toolchain as a separate Xcode download, and a text input that ignores input while the window is in the background (UI automation needs the window frontmost). CI figures come from software or unknown renderers, so do not compare them with the hardware figure or hold them to these budgets. Task 08's file was retired here.

## 2026-10-29 — RSS and binary-size measurement scripts and macOS results
`scripts/measure/measure.sh` (macOS, Linux) and `measure.ps1` (Windows) launch `wisp` twice against a local 64 KiB file, sample RSS idle and after one request, and write one JSON record; `measure.yml` (dispatch only) runs them per target. Committed results: aarch64-apple-darwin measured on a hardware renderer (binary 16,660,480 B, idle ~100 MB, ~103 MB after one request) and x86_64-apple-darwin with binary size only. Failure paths (early exit, no `WISP_EVENT` in 30 s) write `unmeasured` with null RSS and exit 1.
**Cost:** `measure.ps1` was never run (no pwsh here); Windows, Linux and macOS x64 RSS wait on a `measure.yml` run, which needs a remote. x64 macOS RSS under Rosetta is not representative, so do not measure it that way. CI renderers are software, so those figures are not comparable with the hardware one. Unfixed review P3s are listed in PLAN.md under Open from 07.

## 2026-10-29 — GPUI walking-skeleton window wired to the Engine
The `wisp` binary now opens a GPUI window with a method dropdown (the seven `Method` values, GET default), a URL input, Send, a status line and a scrollable body. Send calls `Engine::submit`, and one drain task reads the event receiver, filtered to the latest `RequestId`. The status line shows `<status> <reason> · <ms> ms · <size>` with size in B/KB/MB, or `Error (<kind>): <message>`. The body is lossy UTF-8 truncated at 1 MiB. With `WISP_AUTOSEND_URL` set, the app sends one GET and prints one `WISP_EVENT completed status=<n> size=<bytes>` or `WISP_EVENT failed kind=<kind>` line for task 07; without it, nothing is printed or sent. It landed as one squashed commit (e343eac) with no dependency changes.
**Cost:** Two review rounds. Round 1 asked for sentence-style test names, for ignoring events from stale `RequestId`s (a slow response replaced a newer fast one), and for `format_size` not to show "1024.0 KB" just under 1 MiB. The rounding fix changed the KB/MB test so that every size above 1 MiB showed in KB; round 2 caught it, and tests now cover both sides of the boundary (2 MiB gives "2.0 MB"). Do not decide a unit boundary from the rounded string. The manual window check was done by the orchestrator at bff16ed, with screenshots sent to the user in chat rather than saved under `logs/` as the task asked; it was met in substance (200 OK with body, 501 with HTML body, and a connection-refused error all rendered). Known residuals. The method dropdown has no chevron because no icon assets are configured; cosmetic, for M2. GPUI's text input ignores input while the window is in the background, so any UI automation must have the window frontmost. Error kinds print in Debug form (`kind=Connect`), and task 07's parser must match that. With `WISP_AUTOSEND_URL` set, a late autosend response can overwrite a manual one, which is harmless for the measurement hook. Task 06's file was retired here.

## 2026-10-29 — Minimal core Engine and CI/release workflows
wisp-core now has an Engine that owns a small tokio runtime and one shared rustls reqwest client. `Send` and `Cancel` commands go in, and each request ends in exactly one `Completed` or `Failed` event on an `async_channel`. Errors are classified from the source chain, and the serde types are round-tripped through `serde_json`, a dev-dependency only. Separately, `ci.yml` runs fmt, clippy and tests on ubuntu and macOS, and `release.yml` builds four targets, with x86_64-apple-darwin native on `macos-26-intel`. Every macOS job installs and verifies the Metal Toolchain, actions are pinned to SHAs, and the Linux apt list comes from zed's `script/linux` at the gpui-pre zed-rev.
**Cost:** Task 04 needed three review rounds and a spec amendment. Round 1 found that `classify` keyword-searched the whole error chain including reqwest's URL text, so a request to `/tls` was reported as `Tls`; classify from the source chain, never the URL. It also found two tests that could not fail: the serde test only checked trait bounds at compile time, and the "no Completed after cancel" check passed because the 5 s mock delay outlasted a 100 ms wait. The serde finding led the user to amend the task to allow `serde_json` as a dev-dependency (one root `Cargo.toml` line, one `Cargo.lock` line). Round 2 found the cancel test still passing, because dropping the engine aborts the task and closes the channel, so keep the engine alive and use server-side delays with a sentinel request. It also found the pinned version written as `"1"` instead of `"1.0.154"`. Round 3 found an unreachable `panic!` arm that broke clippy. Do not use client sleeps to wait for state, and do not drop the engine to prove nothing arrives. Task 05's code comment claimed the Intel macOS runner was paid, which nobody had checked; `macos-26-intel` is a standard runner, so the x86_64-apple-darwin job runs natively rather than cross-compiling. Still unverified: the Linux and Windows jobs and a real green `release.yml` run, which cannot happen until the repo is pushed. `libstdc++-14-dev` matches the Ubuntu 24.04 branch of zed's script and needs re-checking when `ubuntu-latest` moves. Each task was squashed to one commit on main. Task 01's file was retired here; its work landed in 0e87d3a.

## 2026-10-29 — Cargo workspace scaffold and trimmed CLAUDE.md
The repository now has a Cargo workspace of wisp-core, wisp-storage and wisp-app (bin `wisp`), all `publish = false`, with the M0 dependency set locked in `Cargo.lock`. GPUI is pinned by exact crates.io version with no git sources: gpui-component =0.8.1, gpui-pre =0.3.10 (exposed as `gpui`) and gpui-pre-platform =0.3.10 (exposed as `gpui-platform`). It builds with `cargo build --workspace --locked`, passes fmt and clippy -D warnings, and has no openssl-sys or native-tls in the graph. Separately, `CLAUDE.md` is under its 50-line cap, with the role descriptions moved to `docs/workflow.md`.
**Cost:** The first attempt pinned gpui and gpui-component by git rev, which forced an old gpui-component (0.5.2): current gpui-component uses the versioned gpui-pre snapshots, so a rev pin of both gave two gpui sources, and a `[patch]` to the same URL is rejected by cargo. Do not go back to git revs. Attempt 1 also failed at verify because gpui-pre ships no platform backend (only `Application::with_platform`); gpui-pre-platform is a separate crate that has to be added, and the `wayland`/`x11` features on gpui-pre are no-ops, so they are enabled on the platform crate instead. macOS uses precompiled Metal shaders (no `runtime_shaders`), which needs Xcode's Metal Toolchain, a separate Xcode download; CI (task 05) installs it. The three task-02 commits were squashed into one so the stale git-rev rationale in the first commit does not survive. Task 03 needed one review round, for a commit-subject prefix.
