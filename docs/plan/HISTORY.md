## 2026-10-30 — Reusable key-value table editor

**Cost:** One review round: the checkbox and delete button were Tab stops by default in gpui-base 0.8.1, so Tab did not go name, value, next name; fixed with `.tab_stop(false)`. Accepted residual: past the virtualisation threshold Tab cannot reach rows outside the viewport. The window hand check waits for task 31 to mount the table. Verified with 188 workspace tests, fmt and clippy clean.

Milestone M1 (tasks 10-20) delivered the frozen core types, pure `resolve`, the body store, the full Engine event set with real cancel, the `toml_edit` storage codec, request, collection and environment storage with git-ignored 0600 secrets, the file watcher, the history log, and a fixture integration test. All of it runs and is tested with no window. User decisions and amendments during M1:
- 10: secret-bearing types print Debug in plain text under a logging rule.
- 11: the 64 KiB cap measures only bytes added by expansion (large literal bodies are fine); every placeholder counts against the 10,000 budget.
- 12: response-body spill files go to a private per-user dir `<temp>/wisp-<uid>` (0700), named `wisp-<pid>-<uuid>.body`, created 0600 with create_new.
- 13: `atomic_write` keeps the target's permissions and follows symlinks, temp files via create_new; `atomic_write_private` creates new files 0600.
- 13: list saves (headers/params) match entries by LCS diff, then pair edits, so comments stay with the right entry.
- 13: `write_auth` keeps its signature; callers skip writing a default auth to a file that had none.
- 14: the nested-rename spurious `Changed` residual was accepted; consumers re-check the disk.
- 17: the sidecar must be a plain file name in the request's folder, and must not resolve to the request file itself.
**Cost:** Wave 2 stalled when the disk filled with per-worktree build output; it was fixed by sharing one `CARGO_TARGET_DIR`. That caused the second mistake: cargo reused another worktree's artefacts and a tester ran a stale binary, so it was fixed by giving each worktree its own target subdirectory. Both are since fixed. Do not run `cargo clean` to recover space; trim worktrees instead.

## 2026-10-30 — Request file storage with sidecar bodies
`load_request` and `save_request` in `crates/storage/src/request.rs` read and write request files, with bodies kept in sidecar files. Saves edit the TOML in place through the codec so comments survive, skip writing default auth when the file had none, and keep settings defaults. Sidecar names must be a plain file name in the request's folder (no separators, `..`, absolute or drive paths), not the request's own name, and symlinks must stay inside the folder; a sidecar that canonicalises to the request file is rejected. These checks run before any read or write. It landed as one squashed commit (019d439).
**Cost:** Review found that unchecked sidecar names let a cloned collection read any file into a request (sent on Send) and overwrite any file on save; two user amendments closed it (name rules, then identity). Residuals (sibling-request overwrite, hard links, `::$DATA`, drive-prefix check, symlink check-then-use race, a duplicate method parser, a `set_current_dir` test) are in PLAN.md. Task 17's file was retired here.

## 2026-10-30 — Collection tree and folder/collection defaults storage
`open_collection` returns a `CollectionTree` of `Node`s with `RequestMeta`; sidecars are never read on open and broken request files become `Node::Invalid`. `collection.toml` and `folder.toml` load and save (default auth is not written when the file had none), and `scope_for` returns folders outermost first. Symlink cycles are skipped through a canonical visited set, and sorting has a deterministic tiebreak.
**Cost:** Review caught a symlink-to-parent loop that made opening a collection never return. The visited set is walk-wide rather than per-path, so sibling symlinks show under whichever name comes first; see PLAN.

## 2026-10-30 — resolve(): variables, path params, inheritance and bounded expansion
Pure `resolve(&Request, &Scope)` applies variable precedence, dynamic vars, path params (multi-param segments, catch-all per-segment encoding, regex warnings), query, header merge, nearest-folder auth inheritance, bodies and settings, and collects all problems. Expansion is bounded: depth 8, 64 KiB cap on bytes added by expansion, 10,000-expansion budget with every placeholder charged.
**Cost:** Three review rounds and two user amendments. Exponential variable fan-out could freeze the UI (14 s growing to hours); then failing leaves bypassed the budget (55-345 s), then empty-name leaves did. The first size cap measured the whole output and wrongly rejected large literal bodies, so it now counts only bytes added by expansion. Do not budget only successful lookups.

## 2026-10-30 — Environment and secrets file storage
`crates/storage/src/environment.rs` lists, loads and saves environments under `environments/`. Edits preserve comments. Secret values go to `<name>.secrets.toml` through `atomic_write_private` (0600), and `environments/.gitignore` keeps them out of git. Names must be ASCII alphanumerics, `-`, `_` and inner `.`, with no `..`, no `.secrets` suffix and no Windows reserved names. Listing skips non-files and invalid names, and logging records names only. Code review was clean after one round; it landed as one squashed commit (25428db).
**Cost:** Review caught that an environment named `dev.secrets` would overwrite `dev`'s secrets file, and that `:` in a name could escape the folder on Windows; both led to the name allowlist. The allowlist rejects names with spaces, so existing ones will not load. Other residuals (symlinked files unlisted, one `file_type` error aborting listing, non-atomic two-file save order, COM0/LPT0, case-insensitive collisions) are in PLAN.md. Task 19's file was retired here.

## 2026-10-30 — Engine full event set, real cancel and per-settings clients
The engine now emits six events: Started, Headers, Progress (throttled), Completed, Failed and Cancelled. Response bodies stream into the `BodyStore`, cancel really aborts the request and emits Cancelled, and `File` and `Multipart` bodies are sent. One `reqwest` client is cached per `ClientSettings`, honouring `verify_tls`, `follow_redirects`, `proxy` and `timeout`. The app reads the first 64 KiB from `bodies()`, releases superseded handles and shows body read errors. Code review was clean after one round; it landed as one squashed commit (2e8d74b). Hardware measurement on macOS arm64 stayed within budget: binary 16,710,288 B, idle RSS 99,232 KiB, 102,560 KiB after one request.
**Cost:** One review round (fix commit 9a704fc, squashed in). Several shortcuts were accepted and are in PLAN.md: spill writes block the async worker, File/Multipart bodies are buffered whole before sending, the client cache builds under a std `Mutex`, and the cache is tested only through `ClientCache::get`. Task 16's file was retired here.

## 2026-10-30 — Collection file watcher
`Watcher::start(root)` in `crates/storage/src/watcher.rs` watches a collection folder and sends `Changed { path }` (relative to the canonicalised root) on an `async_channel`. Events for the same path within 100 ms coalesce into one and are emitted in time order. Paths under `.git/` and the state dir, temp files, and directories themselves are ignored; known directories are scanned at start and on move-in and never walked through symlinks, so a directory rename is not reported as file changes. notify errors are logged, and dropping the `Watcher` closes the channel.
**Cost:** Five review rounds plus one failed verify. Attempt 1 failed verify because directory renames were reported as file changes; each fix after that exposed the next directory edge case: a stale known-directories set, a same-window replace, the rename source, a nested rename, and a walk through symlinks. One residual was accepted by the user: nested directory renames in the same window may emit one spurious `Changed`, so consumers must re-check the disk. Do not try to classify paths at event time alone, because a renamed or deleted directory is already gone from disk; keep the known-directory set.

## 2026-10-30 — Storage TOML codec and atomic file writes
`crates/storage/src/codec.rs` reads and writes `[vars]`, key-value arrays and `[auth]` in place on a `toml_edit` document, so comments and formatting survive; key-value arrays are matched by LCS diff and then paired edits. `crates/storage/src/fs.rs` does typed reads and atomic writes through a same-directory `create_new` temp file and rename, keeping the target's mode and following symlinks, with `atomic_write_private` for secret-bearing files. Code review was clean after two rounds; it landed as one squashed commit (3720e20).
**Cost:** The first `fs.rs` used a predictable temp file that followed symlinks (secrets could be written to an attacker's file) and dropped file modes; review caught both and the fix went in as an amendment. Residuals (reordering, comment loss, spacing, untested Windows readonly path) are in PLAN.md. Task 13's file was retired here.

## 2026-10-30 — Response body store with spill to disk
`crates/core/src/body.rs` adds `BodyStore`, `BodyWriter` and `BodyHandle`. Bodies stay in memory up to the limit, then spill to `<temp_dir>/wisp-<uid>` (mode 0700, ownership and mode checked via `symlink_metadata`) as `wisp-<pid>-<uuid>.body`, created with `create_new` and mode 0600. Handles support range reads and release; files are removed on writer drop and on last-store drop, and a failed write poisons the writer. Code review was clean after one round; it landed as one squashed commit (bb85e0a).
**Cost:** The spill location was first a shared temp path; the user's 2026-10-30 amendment moved it to a private per-user directory, and the review round tightened it. The uid-ownership check has no test because it needs root, three tests spill into the real per-user directory instead of a test base, and the non-unix code path is not compiled here. Task 16 should rely on `BodyStore` ids being process-unique. Task 12's file was retired here.

## 2026-10-30 — Append-only request history log
`crates/storage/src/history.rs` adds `HistoryEntry`, `Outcome` and `HistoryLog`, writing JSON lines to `<collection>/.wisp/history.jsonl` and creating `.wisp/.gitignore`. The log rotates past 4 MiB to `history.1.jsonl`; `read_all` skips malformed and invalid-UTF-8 lines, and `append` recovers from a torn last line. `preview_from` is bounded to 1 KiB on a char boundary. The URL template is stored unresolved, and no secrets, headers or error messages are stored. Code review was clean after one round; it landed as one squashed commit (4198ee4).
**Cost:** The review round fixed robustness gaps (torn last line, invalid UTF-8) rather than design. `preview_from` decodes exactly 1024 bytes, so a 4-byte char straddling the limit becomes U+FFFD; left as an optional P3. Rotation is not safe against concurrent writers (single writer in v1). Never store `ResolveWarning`s in history, because `PatternMismatch.value` can hold a resolved secret. Task 15's file was retired here.

## 2026-10-29 — GPUI walking-skeleton window wired to the Engine
The `wisp` binary now opens a GPUI window with a method dropdown (the seven `Method` values, GET default), a URL input, Send, a status line and a scrollable body. Send calls `Engine::submit`, and one drain task reads the event receiver, filtered to the latest `RequestId`. The status line shows `<status> <reason> · <ms> ms · <size>` with size in B/KB/MB, or `Error (<kind>): <message>`. The body is lossy UTF-8 truncated at 1 MiB. With `WISP_AUTOSEND_URL` set, the app sends one GET and prints one `WISP_EVENT completed status=<n> size=<bytes>` or `WISP_EVENT failed kind=<kind>` line for task 07; without it, nothing is printed or sent. It landed as one squashed commit (e343eac) with no dependency changes.
**Cost:** Two review rounds. Round 1 asked for sentence-style test names, for ignoring events from stale `RequestId`s (a slow response replaced a newer fast one), and for `format_size` not to show "1024.0 KB" just under 1 MiB. The rounding fix changed the KB/MB test so that every size above 1 MiB showed in KB; round 2 caught it, and tests now cover both sides of the boundary (2 MiB gives "2.0 MB"). Do not decide a unit boundary from the rounded string. The manual window check was done by the orchestrator at bff16ed, with screenshots sent to the user in chat rather than saved under `logs/` as the task asked; it was met in substance (200 OK with body, 501 with HTML body, and a connection-refused error all rendered). Known residuals. The method dropdown has no chevron because no icon assets are configured; cosmetic, for M2. GPUI's text input ignores input while the window is in the background, so any UI automation must have the window frontmost. Error kinds print in Debug form (`kind=Connect`), and task 07's parser must match that. With `WISP_AUTOSEND_URL` set, a late autosend response can overwrite a manual one, which is harmless for the measurement hook. Task 06's file was retired here.

## 2026-10-29 — Minimal core Engine and CI/release workflows
wisp-core now has an Engine that owns a small tokio runtime and one shared rustls reqwest client. `Send` and `Cancel` commands go in, and each request ends in exactly one `Completed` or `Failed` event on an `async_channel`. Errors are classified from the source chain, and the serde types are round-tripped through `serde_json`, a dev-dependency only. Separately, `ci.yml` runs fmt, clippy and tests on ubuntu and macOS, and `release.yml` builds four targets, with x86_64-apple-darwin native on `macos-26-intel`. Every macOS job installs and verifies the Metal Toolchain, actions are pinned to SHAs, and the Linux apt list comes from zed's `script/linux` at the gpui-pre zed-rev.
**Cost:** Task 04 needed three review rounds and a spec amendment. Round 1 found that `classify` keyword-searched the whole error chain including reqwest's URL text, so a request to `/tls` was reported as `Tls`; classify from the source chain, never the URL. It also found two tests that could not fail: the serde test only checked trait bounds at compile time, and the "no Completed after cancel" check passed because the 5 s mock delay outlasted a 100 ms wait. The serde finding led the user to amend the task to allow `serde_json` as a dev-dependency (one root `Cargo.toml` line, one `Cargo.lock` line). Round 2 found the cancel test still passing, because dropping the engine aborts the task and closes the channel, so keep the engine alive and use server-side delays with a sentinel request. It also found the pinned version written as `"1"` instead of `"1.0.154"`. Round 3 found an unreachable `panic!` arm that broke clippy. Do not use client sleeps to wait for state, and do not drop the engine to prove nothing arrives. Task 05's code comment claimed the Intel macOS runner was paid, which nobody had checked; `macos-26-intel` is a standard runner, so the x86_64-apple-darwin job runs natively rather than cross-compiling. Still unverified: the Linux and Windows jobs and a real green `release.yml` run, which cannot happen until the repo is pushed. `libstdc++-14-dev` matches the Ubuntu 24.04 branch of zed's script and needs re-checking when `ubuntu-latest` moves. Each task was squashed to one commit on main. Task 01's file was retired here; its work landed in 0e87d3a.
