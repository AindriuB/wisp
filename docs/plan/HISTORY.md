## 2026-11-10 — Persisted cookie file store
`wisp-storage` has a `CookieFile` that loads, saves, enables and disables one collection's cookie file at `cookies/<collection-id>.json` in the per-user data dir. Persistence is off by default and is on exactly when the file exists. Saves are atomic and 0600 in a 0700 directory, drop expired cookies, and refuse a symlinked file. Loads refuse a file over 4 MiB, keep at most 3,000 cookies, skip oversized or domainless entries, and fail cleanly on a corrupt or wrong-version file. `StoredCookie` redacts its value in Debug. The app wiring is task 107.
**Cost:** Code review took one round: a huge `expires` panicked on load, and `save` could write a file that `load` then refused. Amendment 1 (user decision) caps domain at 253 B and path at 1 KiB and makes `save` drop the soonest-expiring cookies first to stay within 4 MiB. Follow-ups are in PLAN under task 102.

## 2026-11-10 — History panel, Clear and Resend
The app has a history panel for the open collection, newest first, showing status (or "Failed: Dns") and relative time. Opening an entry shows a read-only tab marked "From history, <time>" with the stored status and body. Resend sends the stored request with the current environment and the folder defaults, and says "Resent with the current environment (prod)". Clear history asks first, naming the collection. A `history_bodies` setting turns body storage off, after which entries show "Body not stored". Amendment 1 (user decisions, 2026-11-10) widened ownership to core `body.rs` and storage `history.rs`. **Cost:** Code review took two rounds. Round 1: Resend dropped folder defaults, the body was copied into memory, read-only use minted the collection id, and the panel went stale after a collection change. Round 2: the file-backed test did not guard its fix, and a chained resend lost folder defaults. Resend tests exercise the scope helper, not `Workspace::send`, because there is no gpui test harness. One earlier implementer run had a single unnamed failing test that never reproduced (1 of 9 workspace runs); it is unconfirmed, not a known flake. The hand-check wrote `history_bodies = false` into the real user `settings.toml` because that path ignores `WISP_DATA_DIR`; see the P2 follow-up in PLAN.

**PR #38 review round 1 and follow-on rounds:** redacted fields are sanitised on open; the original scope applies only while the URL is unchanged; `BodyError::Removed` and tolerant clear/evict; `prepare_send` is pure with env tests; a redacted body blocks Resend until each redacted leaf is non-empty; the Cmd+Return notice is fixed; the JSON scan is bounded at depth 128 and matches as it goes.

## 2026-11-10 — Per-user history store
History no longer lives in the collection's `.wisp/history.jsonl`. `HistoryStore` writes `history/<collection-id>/index.jsonl` plus `bodies/<id>.bin` and `<id>.req.json` in the per-user data dir (0700/0600). It keeps the unresolved request with auth and secret headers redacted, `Set-Cookie` values in response headers redacted, the response body capped at 1 MiB, and failed and cancelled requests. It evicts by 500 entries and 100 MiB. The app appends on the background executor, resolves the collection id once, and emits one Notice per collection when history is off or an append fails. The old file is left on disk and ignored; the panel, Clear and Resend are task 97.
**Cost:** Review round 1 found two races: concurrent appends at the 500 cap lost an entry and orphaned its files, and concurrent first appends each minted a collection id. Appends are now serialised per store and the id is resolved once before any append. `Set-Cookie` redaction was added mid-task (Amendment 1) on the user's decision. `clear` does not take the append lock yet, and a nameless `Set-Cookie` is not redacted; both are in PLAN.

**PR #35 review round 1:** redaction widened to URL userinfo, credential-named params, vars, form fields and JSON keys, plus a header-name heuristic; added a cross-process file lock and an orphan sweep; eviction is best-effort. Re-review found the lock file was opened without read access, which fails `File::lock` on Windows; fixed by opening it read+write. Templated JSON bodies mask `{{refs}}` before parsing so they are redacted, and unparseable bodies fail closed.

**PR #35 review round 2:** the credential-name test now lives in one shared `wisp_core::redact::is_credential_name`; reviewer items 35-10, 35-11 and 35-12 are fixed, `clear` takes `APPEND_LOCK`, body files are removed only after the index rewrite, and re-review was clean after a test fix.

**Cross-PR review:** importers and the history store now share `wisp_core::redact::is_credential_name`; `import/mod.rs` `is_credential_header` calls it.

**PR #35 review round 4:** bare `{{$uuid}}`-style refs (a leading `$`) are now accepted as refs, so JSON bodies containing them are kept rather than failing closed.

## 2026-11-10 — curl, Postman and OpenAPI importers
`wisp-storage` now imports a curl command line, a Postman collection (and environment) and an OpenAPI document (JSON or YAML) into a Wisp collection, with warnings for anything it does not map. Input is treated as hostile: JSON is capped at 10 MiB and YAML at 2 MiB, nesting depth at 64, expanded bytes (anchors and aliases included) at a 64 MiB budget, requests or operations at 5,000, and a server URL at 64 KiB. YAML is checked by an event-level pass over `saphyr_parser::Parser::next_event()`, which is a direct workspace dependency, and tracks depth and each anchor's expanded size iteratively.
**Cost:** Four review rounds. Rounds 1-3 kept finding crash and memory paths: stack overflows from deep YAML keys, alias amplification (up to several GB from about 1 MB), quadratic or cubic unique-naming loops, and repeated server-variable substitution that grew a URL to 200 MB. Line-based YAML heuristics (a depth pre-scan and an alias-byte estimate) failed twice, because a stray `[` or a multi-line quoted span defeated them; do not retry them, the event-level pass replaced them. Anchored copies had to be charged to the budget too (round 3). Accepted residual: saphyr-parser 0.3.3 buffers every token of a flow collection before emitting an event (scanner.rs:866-880), so the 2 MiB YAML cap bounds the worst case to about 450 MB. Follow-ups are in PLAN under task 94.
PR review round 1 (user) fixed shared path-item `$ref` work and name copies (now charged and capped), refused unsafe file-part paths (absolute, `~`, `..`, drive and UNC), `+` as a space in form data and queries (including Postman query arrays), a redacting Debug for `ImportedEnv`, a 50-environment cap, and byte-capped names.
PR review round 2 (user) fixed imported file parts (now disabled empty parts, never a path), credentials and URL userinfo (now written to the secrets environment, userinfo as Basic auth), shared-ref and curl warning bounds, and a cap on the secret-name base.
PR review round 3 (user) bounded the secret-name input scan, routed Proxy-Authorization and padded keys to secrets, stripped OpenAPI server userinfo, made curl credential options and `--expand-X` consume their argument, and made the unknown-option warning show the name only.
PR review round 4 (user) regenerated the curl option list from `curl --help all` (including short options), dropped query and fragment from the extra-URL warning, made the header credential heuristic mirror the history store's list in PR #35, and stripped userinfo from protocol-relative URLs.
PR review rounds 5-6 (user) sanitised the secret-name field to the variable grammar and capped it; the fallback and the cap are tested.

## 2026-11-10 — Digest and AWS SigV4 auth
Requests can now use Digest (RFC 7616: MD5, SHA-256, SHA-512-256, `userhash`, qop auth) and AWS SigV4 (optional session token) auth, with editor kinds for both. For these two types the engine follows redirects itself: it re-signs same-origin hops and drops all engine-added auth after the first cross-origin hop, so credentials and signatures never reach another origin. Basic, Bearer and ApiKey keep reqwest's redirect path.
**Cost:** The RFC 7616 §3.9.2 example values were computed with the first 256 bits of SHA-512, not real SHA-512/256 (different initial values), so they cannot be reproduced with the real algorithm. The test runs the RFC inputs through the same code with the truncated hash, and real SHA-512/256 is checked separately against the NIST "abc" vector; do not try to make the RFC value match the real algorithm. SigV4 vectors come from the awslabs aws-c-auth v4 test suite. Review round 1 found SigV4/Digest credentials crossing origins on redirects; letting reqwest redirect was abandoned for these types (the user decided the engine follows redirects itself). Round 2 hid the session token in `Signed`'s Debug. Residuals are in PLAN.
PR review round 1 (user) fixed `+` in queries, Digest challenge selection, the real payload hash for non-S3 file and large bodies, and added redirect and signature re-verification tests.

## 2026-11-09 — Ask before discarding unsaved changes on quit and close
Quitting (⌘Q or Ctrl-Q, the macOS Quit Wisp menu item, the window close button) and closing a dirty tab (× button, ⌘W, the palette, the banner) now show "Discard unsaved changes?" with Discard and Cancel when a draft is dirty; clean state quits or closes at once. Two pure helpers (`quit_step`, `close_step`) decide the outcome, a `prompt_up` flag prevents a second prompt, and Discard closes the tab by entity, not by the index captured earlier. On macOS the Wisp menu also gained Hide Wisp (⌘H), Hide Others (⌥⌘H) and Show All. Dock Quit, logout and shutdown cannot be intercepted and are documented in `docs/architecture.md#app-lifecycle` and the README.
**Cost:** The first version registered the global `Quit` handler to call `handle.update` on the window; global listeners run inside the active window's update, so that nested update fails with "window not found" and the app ignored ⌘Q entirely. It is now run through `cx.defer`. `quit-check.sh` did not catch it because it quits through AppleScript `terminate:` and the `WISP_CLOSE_WINDOW_AFTER_MS` hook, never the `Quit` action; do not trust that script for this path. Intercepting `terminate:` needs an objc swizzle, a dependency or a GPUI patch and was ruled out. The open-collection and delete prompts still do not set `prompt_up` (see PLAN).

5. With a dirty tab, click the red window button. Same prompt; Cancel keeps the app, Discard quits.

8. (Task 88) At a 720x480 window the sidebar stops at 240 when dragged wide; the request/response split stops at 240 wide (or 140 high in vertical layout); the Cookies scrollbar is visible in a narrow pane (under 584 px) without scrolling sideways.

## 2026-11-09 — Storage rejects Windows-unsafe and aliasing names
Sidecar body files are now rejected (`StorageError::Invalid`, key `body.file`) on load and save when the name ends in a dot or space, has a Windows reserved device stem, resolves to a `.toml` file (including Windows 8.3 short names), or is a Unix hard link to the request or any sibling `.toml`. One reserved-name helper in `fs.rs` covers CON, PRN, AUX, NUL, COM0-9 and LPT0-9 (and superscript forms) and is used by environment names and by create, rename and move in `ops.rs`.
**Cost:** The hard-link rule is Unix-only because std has no stable file-identity API on Windows and we added no dependency. The first acceptance test renamed `b.toml` to `B.TOML` and then read `b.toml`, which failed on case-sensitive Linux; the production check was right. The 8.3 alias test is best-effort and depends on the volume having short names on (see PLAN follow-ups). Do not rely on the symlink-to-`.toml` check alone for Unix; the dev/ino check is what the tests actually exercise.

## 2026-11-09 — Secrets redacted from Debug output in wisp-core
`Auth` (password, token, API key value), `ClientSettings.proxy` userinfo, `Header` values, `PreparedRequest` (query and body bytes, which print as a length) and `ResolveWarning::PatternMismatch.value` now have hand-written Debug impls that print `<redacted>`. `Request`, `FolderDefaults`, `CollectionDefaults`, `Command` and `Event` keep derived Debug and are safe through those fields; `Event::Headers` holds `Vec<Header>`, so its values are now redacted too. Each row has a `debug_redacts_*` test, plus composite tests; the proxy redaction also handles schemeless proxy URLs. wisp-storage has no secret-bearing type of its own. Tester passed 386 tests with no flakes; no dependency changes.
**Cost:** The task file's Notes said `Event::Headers` values were unredacted; that was wrong, since they are `Header` values. The reviewer found the schemeless proxy leak, fixed in the second commit. Not fixed, listed in PLAN: multipart text values, URL path and userinfo secrets, `EngineError` messages carrying the URL, `ResponseCookie` derived Debug, and proxy passwords with an unencoded `/`, `?` or `#`. `ClientSettings` must keep its `Hash`/`Eq` derives (client-cache key), so only Debug was replaced.

## 2026-11-09 — Streamed bodies are resent on 307/308 redirects
With follow-redirects on, a File or Multipart body over 1 MiB is now resent on a 307 or 308: the engine re-opens each file, checks its length against the first send, and streams it again to the new URL, up to 10 hops. A cross-origin resend drops Authorization, Cookie, Cookie2, Proxy-Authorization and WWW-Authenticate, the same set reqwest strips. A file that changed length fails with `BodyFile`; before, the 3xx was shown as the result.
**Cost:** The first version stripped only Authorization and Cookie, copied from the task's table; review found reqwest 0.13.5 strips five headers (redirect.rs:241-249), so the set must follow reqwest, not the table. The length check does not detect same-size edits, and custom auth headers such as `X-Api-Key` still cross origins; both are in PLAN. PUT/PATCH on 301/302 remains unhandled.

## 2026-11-03 — Quit action, macOS app menu, and no windowless app
Wisp now has a Quit action bound to cmd-q on macOS and ctrl-q elsewhere, a macOS "Wisp" app menu with Quit, and every window close routed through `cx.quit()`, so the app can no longer be left running with no window. Before, there was no Quit action, no menu and no Cmd-Q, and closing the window left the process alive. On a Touch Bar Mac (macOS 27.0.1, MacBookPro17,1), Dock Quit in that state aborted inside AppKit's Touch Bar finder. `scripts/measure/quit-check.sh` launches a test bundle and checks it exits cleanly with no new crash report. The user's hand test on the Touch Bar MacBook Pro passed on 2026-11-03: the red close button, Cmd-Q and Dock right-click Quit all quit cleanly on a build with a test bundle id, with no new crash report.
**Cost:** The crash cause comes from reading source, not from a debugger: `accesskit_macos` restores the content view's class when the window drops, which breaks AppKit's KVO and the Touch Bar finder then throws. That is an upstream accesskit/GPUI bug and is not reported upstream yet; the fix avoids the teardown-while-running state rather than repairing it, so do not try to patch accesskit here. A crash at 22:11 during the hand test came from the earlier signed build (binary UUID e767c41b), which still has the bug, and is consistent with the fix. Residuals: quitting by any route discards unsaved drafts without a prompt (not a regression; candidate follow-up "confirm discard on quit"); the `WISP_CLOSE_WINDOW_AFTER_MS` hook calls `quit_app` directly, so the automated check does not exercise the close button (the hand test covers it); there are no About or Hide menu items because GPUI 0.3.10 `OsAction` lacks them (`App::hide` exists for a later Cmd-H); shellcheck SC2010 (`ls | grep`) in `quit-check.sh`.
